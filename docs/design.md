# design.md — 鳥取市テニス協会 公式サイト デザインガイドライン（Ver.2 / 水色ベース）

> 実装・デザイン生成の唯一の基準。参考サイト（ACES Inc. / ds-k.site）から取り入れるのは
> **余白・階層・落ち着き**という骨格だけで、色・書体・モチーフは本書の定義を使う。丸写しは不可。

---

## 0. このサイトが果たす仕事

**「いま申し込める大会を見つけて、申し込む」** — トップページの仕事はこれ一つ。
読み手は鳥取市周辺で試合に出る20代〜70代の男女。スマホからの閲覧が大半で、多くはコートか通勤中に見ている。
**若さや先進性より、正確さと見つけやすさに価値がある。**

---

## 1. デザインコンセプト

### 「空色のコートと、勝ち上がる線」

- **水色（スカイブルー）**をベースカラーとする。青空の下の屋外コート、鳥取の空と水（日本海・湖山池）、
  そして国際大会の標準となった**ブルーコート**。ブルーコートが世界標準になった理由は
  「オプティックイエローのボールが最も見えやすい色」だから — 水色×ボール黄という配色は、
  テニスにおいて最も機能的な組み合わせでもある。
- このサイトにしかない視覚言語は**ドロー表（トーナメントブラケット）の枝線**。
  勝ち上がりが右へ収束していくあの線を、装飾ではなく構造として使う。
- 余白を大胆に取り、1画面1メッセージ。情報を詰め込まない。

## 2. カラートークン

```css
--sky-50:   #F2F9FC;  /* 背景。ほぼ白の水色 */
--sky-100:  #E0F1F8;  /* 淡い面。セクション切替・告知バー地 */
--sky-200:  #BFE3F2;  /* カード地・罫・ホバー面 */
--sky-400:  #56AED6;  /* 水色。図版・装飾線・アイコン */
--court:    #1272A6;  /* メイン。リンク・ボタン・バッジ（白地上 5.27:1） */
--court-deep:#0A4D74; /* 濃色面・フッター・見出し補助（白文字 9.03:1） */
--navy:     #0B2B3C;  /* 文字色。ほぼ黒の紺（--sky-50上 13.85:1） */
--ink-sub:  #3D6273;  /* サブテキスト（--sky-50上 6.18:1） */
--line:     #FFFFFF;  /* コートラインの白。濃色面上の罫・ブラケット線 */
--ball:     #D9E021;  /* オプティックイエロー。アクセント（--navy文字 10.27:1） */
--alert:    #C4462F;  /* 中止・締切間近・LIVE。警告のみ（白文字 4.92:1） */
```

### 使用ルール（厳守）

1. **`--ball` は「いま動いているもの」にしか使わない。** 受付中バッジ・主要CTA・現在地インジケータ、以上。
   ボールの黄は「試合中」の色であって飾りではない。面積で使うと安っぽくなる。**全体の3%以下。**
2. `--sky-100` / `--sky-200` は面（セクション背景・カード地）に使い、文字色には使わない。
3. `--sky-50` を基調とし、`--court-deep` の濃色面は**1ページに2〜3ブロックまで**。
4. **グラデーションは使わない**（初版のヒーローグラデは廃止。フラットな面で構成する）。
   ドロップシャドウは `0 1px 2px rgba(11,43,60,.08)` まで。
5. コントラストは常に 4.5:1 以上。`--sky-200` の上に `--court` の文字を置かない（比率不足）。
   `--sky-400` は装飾専用で、テキストには使わない。

## 3. タイポグラフィ

| 役割 | 書体 | ウェイト | 使いどころ |
|---|---|---|---|
| ディスプレイ（和文見出し） | **Zen Kaku Gothic New** | 700 / 900 | ページ見出し、セクション見出し、大会名 |
| 本文 | **BIZ UDPGothic** | 400 / 700 | 本文、要項、表 |
| 数字・欧文 | **Barlow Condensed** | 500 / 600 | 日付、スコア、締切、年度、英字ラベル |

- 本文に**UDフォント**を選ぶのは意匠ではなく実務判断。会員の年齢層が20代〜70代に広く、
  可読性のために設計された書体を本文に据える。
- **日付とスコアには専用書体を割り当てる。** このサイトで人が探しているのは「いつ」「締切は」「誰が勝ったか」。
  数字を和文の中に埋もれさせない。Barlow Condensed の縦長字形は日付ブロックを小さな面積で強く見せる。

### 型スケール（PC / スマホ）

```
ヒーロー見出し    48 / 32 px   Zen Kaku 900   letter-spacing: -.02em  line-height: 1.3
ページ見出し      36 / 26 px   Zen Kaku 700
セクション見出し  26 / 21 px   Zen Kaku 700
大会名            20 / 18 px   Zen Kaku 700   word-break: keep-all
本文              17 / 16 px   BIZ UDP 400    line-height: 1.9  ← 妥協しない
補足・キャプション 14 / 13 px   BIZ UDP 400
日付（大）        44 / 36 px   Barlow Cond 600
ラベル・バッジ    13 / 12 px   Barlow Cond 600  letter-spacing: .08em  大文字
```

- 和文Webフォントはサブセット分割＋`font-display: swap`。プリロードは Zen Kaku 700 のみ。

## 4. レイアウト

- コンテンツ最大幅 **1120px**（本文主体ページは 760px）。左右余白 PC 40px / SP 20px。
- 縦リズムは 8px グリッド。セクション間 PC 112px / SP 64px。
- **カードの角丸は 4px（ほぼ直角）。** コートラインは直線。ピル型ボタン・大きな角丸は使わない
  （初版の 16px 角丸・ピル型は廃止）。ボタンの角丸も 4px。
- 罫線 1px。`--sky-200` または `rgba(11,43,60,.12)`。
- スマホ最下部に**固定CTAバー**（「● 受付中の大会 N件」）。受付中の大会が存在するときだけ表示。

### トップページ構成

```
[緊急告知バー]  --sky-100地。settings.siteNotice があるときだけ表示
[ヘッダー]      ロゴ｜大会 / 協会登録 / 教室・イベント / 協会について / お問い合わせ｜[エントリー]
[ヒーロー]      実写（当面は水色のコート俯瞰グラフィック）＋受付中大会カード
                左下からブラケット線（白1px）が合流しながらカードへ接続【シグネチャ】
[大会・エントリー] 日付ブロック＋大会名＋会場＋状態バッジのリスト（最大4件）
[お知らせ]      カテゴリチップ＋日付＋タイトル（最大5件）
[協会登録]      --court-deep 濃色帯。個人登録 / クラブ登録 の2CTA
[教室・イベント] 2カード（水曜テニス教室 / テニスの日）
[大会日程]      Googleカレンダー埋め込み（枠線を消して馴染ませる）
[リンク集]      ロゴを統一サイズの器に整列。通常グレースケール、hoverで原色
[フッター]      --court-deep
```

## 5. シグネチャ要素：ブラケット線

**このサイトが記憶される、ただ一つの要素。ここ以外では冒険しない。**

- ヒーロー：左下から白1pxの線が2本 → 合流して1本 → 受付中大会カードへ接続。
  読み込み時に `stroke-dashoffset` で0.9秒かけて描画。イージング `cubic-bezier(.16,1,.3,1)`。1回だけ。
- セクション見出しの左に、ブラケットの一片（`┐` を1px線・高さ1em）を置く。
  「この先が枝分かれする」という階層の記号として使う。
- 大会カードのホバー：右端から短い枝が16px伸びる（150ms）。

---

## 6. アニメーション（この3つ以外入れない）

1. ヒーローのブラケット線描画（読み込み時1回）
2. 大会カードのホバー枝線（150ms）
3. セクション見出しのフェードアップ（IntersectionObserver・`translateY 12px→0`・400ms・1回のみ）

- パララックス、カウントアップ、スクロールジャック、常時ループはすべて禁止。
- GSAP等のアニメーションライブラリは入れない（CSS＋数行のJSで足りる）。
- `@media (prefers-reduced-motion: reduce)` で全て無効化し、最終状態で静止表示。
- **過剰なアニメーションは「AIが作った感」を最も強める。入れないことが品質。**

## 7. 状態表現（大会ステータス・7状態）

日時から自動算出される状態（00_全体設計.md §4）を、色と語で一貫して表す。

| 状態 | ラベル | 色 |
|---|---|---|
| announced | 開催予定 | `--sky-100` 地 / `--navy` 文字 |
| open | ● 受付中 | `--ball` 地 / `--navy` 文字 ← **黄はここが主役** |
| closing | ● 締切間近 | `--alert` 地 / 白文字 |
| closed | 受付終了 | `rgba(11,43,60,.08)` 地 / `--navy` 60% |
| draw | ドロー公開 | `--court` 地 / 白文字 |
| live | ● 開催中 | `--alert` 地 / 白文字（点滅させない） |
| finished | 結果 | `--court-deep` 地 / 白文字 |

**語は全ページで統一する。** 「エントリーする」で始めたら完了画面も「エントリーを受け付けました」。
「申込」「応募」と混ぜない（content.md §12 の統一表に従う）。

## 8. 文章のトーン

- **敬体（です・ます）**。協会からの連絡としての正確さを最優先。
- ボタンは動詞で、起きることをそのまま書く。「送信」ではなく「エントリーする」。「詳細」ではなく「要項を見る」。
- 空の状態は誘導に使う。「受付中の大会はありません」で止めず「次回の受付は9月上旬を予定しています」まで書く。
- エラーは謝らず、何が起きて何をすればいいかだけを書く。
- 元号と西暦：**見出しは元号（令和8年度）、日付データは西暦（2026.08.12）**。協会の慣行が元号であり、
  西暦への統一は利用者本位ではない。

---

## 9. 画像ルール

1. **文字を画像に載せない。** 要項・ドロー・結果・役員名簿はテキスト／表で作る。画像は写真だけ。
2. 原本には手を加えずそのままアップロード（更新者側のリサイズ・圧縮・加工アプリ禁止。これが端末依存の発生源）。
3. 写真は横長 3:2 / 16:9、`object-fit: cover`。`width`/`height` を必ず出力し CLS を防ぐ。
4. ファーストビュー以外は `loading="lazy"` `decoding="async"`。
5. **実写を使う。生成AI画像は使わない。** 競技団体の公式サイトでは実写が信頼性そのもの。
   実在しない選手・コートの画像は会員に対する誠実さを損なう。生成を許すのは背景の抽象パターンのみ。
6. スクリーンショットで結果を貼らない。表入力を使う。

---

## 10. アクセシビリティ

- コントラスト比 4.5:1 以上（§2 のトークンは検証済みの組み合わせのみ使う）
- フォーカスリング可視化（`outline: 2px solid var(--court); outline-offset: 2px`）
- ナビ・タブ・アコーディオンはキーボード操作可能に
- 状態は色だけでなくテキストでも明示（バッジに必ずラベル文字を入れる）
- タップ領域 44px 以上

---

## 11. やらないこと

- グラデーション背景・ピル型ボタン・大きな角丸（初版から廃止）
- クリーム地＋明朝＋テラコッタ／黒地＋蛍光色（どこにでもある配色）
- 全幅の動画背景、パーティクル、カーソル追従
- 意味のないアイコン・絵文字（🎾 等）の併記
- ストックフォトの外国人プレイヤー写真
- 数字マーカー（01/02/03）… 順序に意味がない箇所には使わない。回戦表示は例外
